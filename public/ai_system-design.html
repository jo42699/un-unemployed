AI System Design


1. Design ChatGPT: Training to Serving (End to End)

Designing a system like ChatGPT requires orchestrating several stages that begin with large scale pretraining and end with low latency inference serving. Pretraining uses massive corpora to teach the model general language understanding, while supervised fine tuning and preference optimization shape the model into a conversational assistant. The serving layer must handle token streaming, batching, caching, and load balancing so the system remains responsive under heavy traffic.

End-to-end design starts with data and model lifecycle. At the training stage, you need a data pipeline that continuously ingests, cleans, deduplicates, and filters text from multiple sources (web, books, code, chat logs). This feeds into distributed training infrastructure (GPU clusters with tensor and pipeline parallelism) that can handle very large models and long training runs. Checkpointing, experiment tracking, and evaluation on held-out benchmarks are essential to detect regressions early and compare model variants.

After pretraining, supervised fine-tuning and preference optimization (e.g., RLHF or DPO) turn the raw model into a safe assistant. This requires a labeling platform for human feedback, safety red-teaming, and policy definition. On the serving side, you design a inference platform that supports streaming tokens, dynamic batching, KV-cache reuse, and autoscaling. Requests flow through authentication, safety filters, routing, and a scheduler that groups compatible requests into GPU batches. Monitoring (latency, throughput, error rates, safety violations) and continuous evaluation close the loop so new model versions can be rolled out safely and rolled back if needed.

2. Design a RAG System (Chat with Your Documents)

A retrieval augmented generation system combines an embedding model, a vector store, and an LLM to answer questions using external knowledge. The system first converts documents into dense embeddings that capture semantic meaning, then stores them in a vector index optimized for similarity search. At query time, the user question is embedded and matched against the index to retrieve relevant passages. The LLM receives both the query and retrieved context, allowing it to ground its reasoning in factual information and reduce hallucinations.

The core of a RAG system is the document ingestion and indexing pipeline. Raw documents (PDFs, web pages, emails) are normalized, chunked into semantically coherent segments, and enriched with metadata (source, timestamp, author, section type). Each chunk is embedded using a text encoder and stored in a vector database that supports approximate nearest neighbor search. Good chunking and metadata tagging are crucial so retrieval returns passages that are both relevant and self-contained.

At query time, the system embeds the user question, performs similarity search, and may apply reranking based on recency, source reliability, or user-specific preferences. The LLM is then prompted with the question plus retrieved context, along with instructions to quote sources and avoid hallucinations. You can add caching of embeddings and retrieval results, multi-hop retrieval (where the model asks follow-up queries), and per-tenant indexes for multi-tenant scenarios. Evaluation focuses on answer correctness, citation quality, and robustness to conflicting or missing information.

3. Design Memory for a Personal AI Assistant

Memory for a personal assistant involves storing structured information about user preferences, past interactions, and long term goals. The system must distinguish between short term conversational context and durable memory that persists across sessions. A memory module typically uses embeddings to represent user statements and a retrieval mechanism to surface relevant memories during future conversations.

A good design separates ephemeral context (current conversation, recent turns) from durable memory (preferences, biography, recurring tasks). Ephemeral context lives in the dialogue state and is passed directly to the model; durable memory is stored in a database or vector store with schemas for facts (e.g., “likes morning workouts”), relationships, and timelines. Each candidate memory is embedded and indexed so the assistant can retrieve relevant items based on the user’s current query.

The system also needs policies for memory lifecycle: when to create a memory (e.g., explicit user request or repeated patterns), when to update or merge, and when to forget or archive outdated information. Users should be able to inspect and delete memories to maintain trust. During inference, a memory retrieval step runs before the main LLM call, selecting a small set of relevant memories to inject into the prompt. This improves personalization, reduces repetitive questions, and makes the assistant feel like a long-term companion while still respecting privacy and user control.

4. Design a Deep Research Agent

A deep research agent performs multi step reasoning across large information spaces. It decomposes a broad question into smaller subproblems, retrieves information from multiple sources, and synthesizes findings into a coherent answer. The agent must maintain an internal scratchpad to track hypotheses, evidence, and intermediate conclusions.

Architecturally, you design the agent as a controller loop around an LLM. The controller maintains a task state (subquestions, sources consulted, evidence collected) and uses the LLM to propose next actions: search queries, document selection, data transformations, or hypothesis updates. Tool integrations include web search, document retrieval, code execution for data analysis, and possibly structured knowledge bases. The scratchpad is stored as a structured log (JSON or a graph) that records each step, making the reasoning process auditable.

To balance exploration and precision, you can implement strategies like breadth-first exploration of subtopics, confidence scoring for evidence, and stopping criteria when marginal gains drop. The final answer is generated by prompting the LLM with the curated scratchpad, asking it to synthesize a clear, cited summary. Evaluation looks at factual accuracy, coverage of relevant sources, and transparency of reasoning. This design turns the agent into a systematic researcher rather than a single-shot answer generator.

5. Design a Multi-Agent Customer Support System

A multi agent customer support system assigns specialized agents to different tasks such as triage, troubleshooting, escalation, and summarization. Each agent has its own capabilities and decision boundaries, and a coordinator agent routes user queries to the appropriate specialist. The system must define communication protocols so agents can share context and avoid redundant work.

The core idea is to model the system as a orchestrated workflow. A front-door triage agent classifies incoming requests (billing, technical issue, account access, complaints) and gathers key details. Based on this classification, the coordinator routes the case to specialized agents: a troubleshooting agent that interacts with knowledge bases and diagnostic tools, an escalation agent that decides when to involve humans, and a summarization agent that produces concise case notes and customer-facing updates.

Agents communicate via structured messages (JSON payloads with intent, context, and results) rather than free text, which keeps the workflow deterministic and debuggable. Parallelization is possible: for complex issues, multiple agents can work concurrently on different aspects (e.g., log analysis and policy checks). Monitoring tracks resolution time, handoff counts, and customer satisfaction. This multi-agent design improves reliability and scalability compared to a single generalist model, while still allowing humans to intervene at key points.

6. Design an On-Device AI Assistant

An on device assistant requires models optimized for limited compute, memory, and power. Quantization, pruning, and distillation reduce model size while preserving quality. The system must implement efficient token generation pipelines that minimize latency on mobile hardware. Privacy is enhanced because user data stays on the device, but the assistant must still handle updates and synchronization with cloud services. Designing for offline capability requires careful selection of tasks that can run locally without external retrieval.

7. Design a Multimodal Search System (Text, Image, Video)

A multimodal search system uses encoders for text, images, and video to create unified embeddings that allow cross modal retrieval. The system must normalize embeddings so similarity scores remain meaningful across modalities. Video search requires extracting key frames or temporal embeddings that capture motion and scene changes. The retrieval engine must support large scale indexing and fast approximate nearest neighbor search. Multimodal search improves user experience by allowing queries like describing an image in text or finding videos related to a concept.

8. Design an LLM Inference Platform (vLLM-as-a-Service)

An inference platform uses optimized kernels, continuous batching, and memory efficient attention to maximize throughput. The scheduler groups requests into batches so the GPU processes multiple sequences in parallel. The system must manage key value caches for attention layers to avoid recomputing past tokens. A robust platform also includes autoscaling, model versioning, and monitoring for latency and token generation speed. Designing such a platform requires deep understanding of transformer internals and GPU memory behavior.

9. Design an LLM Evaluation Platform

An evaluation platform measures model quality using benchmarks, human feedback, and automated metrics. It must support diverse task types such as reasoning, summarization, coding, and safety evaluation. The system stores evaluation results in a structured format so trends can be analyzed over time. A good platform also includes adversarial testing to uncover failure modes. Continuous evaluation ensures that model updates improve performance without introducing regressions.

10. Design a Text-to-Image Generation Service

A text to image service uses diffusion or transformer based models to generate images from natural language prompts. 13. Design an AI Coding Agent

“An AI coding agent must combine code generation, static analysis, and execution feedback.” This system is fundamentally a multi‑step reasoning loop wrapped around an LLM. The agent must be able to understand project context, propose code changes, execute tests, interpret errors, and refine its output. Unlike single‑shot code generation, a coding agent behaves more like a junior developer who iterates until the solution works.

Architecturally, the agent includes a planning module that decomposes tasks into steps (e.g., “read file”, “modify function”, “run tests”). A tool layer provides access to the filesystem, compilers, linters, dependency graphs, and test runners. The agent maintains a state log of attempted changes, errors encountered, and hypotheses about what to fix next. Safety guardrails prevent destructive operations such as deleting critical files or executing unsafe code.

The refinement loop continues until tests pass or the agent reaches a confidence threshold. Evaluation focuses on correctness, reproducibility, and the agent’s ability to handle multi‑file, multi‑step tasks.

15. Design a Content Moderation System Using AI

“Content moderation systems use classifiers and LLMs to detect harmful, unsafe, or policy violating content.” Moderation requires a multi‑stage pipeline that can handle text, images, audio, and video in real time. Because false positives have major user‑experience consequences, the system must be both strict and fair.

The pipeline typically includes pre‑filters (keyword or rule‑based), ML classifiers (toxicity, violence, hate speech), and LLM reasoning layers for nuanced cases. High‑risk outputs are routed to human reviewers. The system must maintain detailed logs for auditing, appeals, and regulatory compliance.

Continuous retraining and red‑teaming ensure the system adapts to new forms of abuse. Evaluation focuses on precision, recall, fairness, and latency.

25. How do you design for latency vs quality trade-offs in AI systems?

Designing for latency versus quality requires balancing model size, decoding strategy, and retrieval complexity. Larger models produce higher quality outputs but increase inference time. Systems often use techniques like caching, batching, and quantization to reduce latency without sacrificing too much quality. Some applications use tiered models where a smaller model handles simple queries and a larger model handles complex ones. Good design ensures users receive fast responses while maintaining acceptable accuracy.

26. How do you implement caching strategies for LLM applications?

Caching strategies store repeated prompts, embeddings, or retrieval results to reduce redundant computation. Systems often cache key value attention states for long conversations so the model does not recompute past tokens. RAG systems cache document embeddings and search results to accelerate retrieval. Effective caching requires eviction policies and monitoring to ensure cache entries remain relevant. Good caching design improves throughput and reduces cost.

27. How do you design rate limiting and cost management for AI APIs?

Rate limiting ensures fair usage and prevents system overload by controlling how many requests each user can send. Cost management requires tracking token usage, model selection, and request patterns. Systems often implement quotas, usage dashboards, and alerts to help users manage consumption. A good design also includes fallback models to reduce cost when high quality is not required. These strategies ensure predictable billing and stable system performance.

28. How do you handle failover and fallback strategies for AI systems?

Failover strategies redirect traffic to backup models or regions when primary systems fail. Fallback strategies use smaller or simpler models when the main model is unavailable. The system must detect failures quickly using health checks and monitoring. A robust design ensures users still receive responses even during outages. These strategies improve reliability and maintain user trust.

29. How do you design an AI system for high availability and fault tolerance?

High availability requires redundant infrastructure, distributed serving, and automatic recovery mechanisms. Fault tolerance ensures the system continues operating even when components fail. The platform must replicate data across regions and use load balancers to distribute traffic. Monitoring and alerting help engineers respond to issues quickly. Good design minimizes downtime and ensures consistent service.

30. How do you design an AI system that gracefully degrades when the model is unavailable?

Graceful degradation ensures the system provides partial functionality when the main model cannot respond. The system may return cached answers, use smaller models, or provide rule based responses. It must detect outages and switch modes automatically. Designing fallback behavior prevents complete service disruption and maintains user experience. This approach is essential for mission critical applications.

34. How do you design a RAG system that handles conflicting information across sources?

The LLM must be instructed to cite sources and explain disagreements rather than merging them into a single narrative.
